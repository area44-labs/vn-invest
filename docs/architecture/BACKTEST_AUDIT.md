# Backtest Engine Audit — Point-in-Time & Execution Integrity

## 1. Backtest Architecture Overview

The repository features two distinct backtesting modules:

1. **Stock-Level Backtest Engine** (`scripts/lib/backtest.py`): Measures historical signal accuracy, forward return outcomes (5D, 10D, 20D), market execution eligibility, confidence calibration, and component attribution across individual stocks.
2. **Portfolio-Level Backtest Engine** (`scripts/lib/portfolio_backtest.py`): Evaluates equal-weighted multi-stock portfolio strategies, selection tie-breaking, position allocation caps, transaction costs, and slippage.

## 3. Backtest Metrics Semantics & Two-Tier Validation Strategy

### Portfolio Backtest Descriptive Metric Semantics

`aggregate_portfolio_results()` in `scripts/lib/portfolio_backtest.py` computes `sequential_compounded_descriptive_return` ($\prod (1 + r_i) - 1$).

- **Explicit Semantics Warning:** This is a descriptive compounded return metric calculated across evaluation dates. Because forward evaluation windows (e.g., 5D, 10D, 20D) across consecutive evaluation dates may overlap:
  1. It is explicitly documented as a descriptive strategy benchmark comparison.
  2. It is **NOT** a realized account equity curve, CAGR, or tradable portfolio cash balance.
  3. Overlapping forward windows mean consecutive period returns are not mutually independent account cash realizations.

### Two-Tier Backtest Refactoring Validation Strategy (Phase 4)

Phase 4 refactoring enforces a strict two-tier validation methodology:

1. **Layer A — Behavioral Parity:** Characterization parity tests against golden fixtures ensure refactored code preserves identical output behavior for all characterized test cases within explicit floating-point tolerance rules (`old_output == new_output`).
2. **Layer B — Quantitative Correctness Validation:** Independent verification of financial assumptions (look-ahead isolation, execution timing, transaction cost deduction, adverse slippage, point-in-time universe membership `Universe(as_of=T)`, and overlapping window accounting). Characterization parity alone does not prove strategy financial correctness.
