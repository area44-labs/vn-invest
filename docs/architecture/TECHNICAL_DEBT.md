# Technical Debt Inventory

This document provides a comprehensive inventory of technical debt identified across the repository during the audit phase. No items in this inventory have been modified or refactored during Phase 0.

| ID        | Severity     | Area                   | Problem                                                                                                    | Evidence                                                                                                                                                                                                                                                                 | Impact                                                                                                                                                                                                                                  | Proposed Direction                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| --------- | ------------ | ---------------------- | ---------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **TD-01** | **CRITICAL** | Quant Engine           | Circular import dependency between `risk.py` and `recommendation.py`.                                      | `scripts/lib/risk.py` imports `VALID_MARKET_REGIMES` and `calculate_risk_adjusted_score` from `scripts.lib.recommendation` inside `normalize_universe_liquidity_scores()`. `scripts/lib/recommendation.py` imports `calculate_t25_risk_metrics` from `scripts.lib.risk`. | Bidirectional runtime dependency loop. Prevents independent execution, clean import isolation, and isolated testing of the risk module.                                                                                                 | Remove all module-level and runtime dependencies from `risk.py` to `recommendation.py`. Move shared scoring functions (`calculate_risk_adjusted_score`) and constants (`VALID_MARKET_REGIMES`) into `scripts/lib/config.py` or a new `scripts/lib/scoring.py` module, establishing a clean unidirectional import graph (`config` -> `risk` -> `scoring` -> `recommendation`). Enforce isolation with an import test (`assert "scripts.lib.recommendation" not in risk_imports`). |
| **TD-02** | **HIGH**     | Pipeline Orchestration | `scripts/generate_report.py` is a 600+ line God module with excessive responsibilities.                    | Contains CLI parsing, snapshot loading, historical report generation, pipeline execution, history index management, monitoring execution, schema validation, and file persistence.                                                                                       | Difficult to unit test and maintain; changes to historical report logic risk breaking daily production runs.                                                                                                                            | Decompose `generate_report.py` into distinct modules: `pipeline_orchestrator.py`, `snapshot_loader.py`, `report_writer.py`. Invariant: `generate_report.py` and orchestrators must not contain quantitative business logic.                                                                                                                                                                                                                                                      |
| **TD-03** | **HIGH**     | Data Boundary          | Hardcoded candidate stock universe list in source code (`scripts/lib/vietnam_market.py`).                  | `UniverseProvider.get_default_universe()` defines a static list of 30 stock dictionaries inside python code.                                                                                                                                                             | Adding or modifying tracked stocks requires python source code edits and deployment. Does not support point-in-time historical universe membership (`Universe(as_of=T)`), introducing survivorship bias risk in long-horizon backtests. | Externalize universe candidate definitions into JSON/YAML configuration files and introduce point-in-time historical universe resolution (`Universe(as_of=T)`).                                                                                                                                                                                                                                                                                                                  |
| **TD-04** | **HIGH**     | Schema Contract        | Schema & Type contract drift between Python backend and TypeScript frontend interfaces.                    | Python `VALID_MARKET_REGIMES` includes `"NEUTRAL"`, whereas `src/types/recommendation.ts` defines `MarketRegime` as `"STRONG_BULL"                                                                                                                                       | "BULL"                                                                                                                                                                                                                                  | "DEFENSIVE"                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | "BEAR" | "PANIC"`, omitting `"NEUTRAL"`. | Manual interface synchronization leads to silent contract drift and runtime state errors. | Implement automated build-time generation of TypeScript types (`src/types/recommendation.ts`) directly from `schemas/recommendations.schema.json` using `json-schema-to-typescript` in Phase 6. |
| **TD-05** | **MEDIUM**   | Frontend Loader        | Frontend loader contains fallback synthetic data generation (`src/data/loader.ts`).                        | `src/data/loader.ts` generates dummy recommendation objects when network fetch fails.                                                                                                                                                                                    | Risks displaying stale or misleading mock quantitative recommendations to end-users if build artifacts are missing.                                                                                                                     | Remove synthetic fallback recommendation generators from frontend loader; throw explicit errors in SSG or display explicit empty/error UI states.                                                                                                                                                                                                                                                                                                                                |
| **TD-06** | **MEDIUM**   | Quant Engine           | Quantitative configuration parameters are re-exported in `recommendation.py`.                              | `SIGNAL_MODEL_VERSION`, `SIGNAL_WEIGHTS`, etc., are defined in `config.py` and re-assigned in `recommendation.py`.                                                                                                                                                       | Creates import redundancy and confusion over canonical parameter sources.                                                                                                                                                               | Standardize all parameter imports directly from `scripts.lib.config`.                                                                                                                                                                                                                                                                                                                                                                                                            |
| **TD-07** | **MEDIUM**   | Quant Engine           | In-place mutation of recommendation payloads during universe liquidity score normalization.                | `normalize_universe_liquidity_scores` in `scripts/lib/risk.py` mutates recommendation dictionary items in-place (`r['risk_metrics']['liquidity_score']` and `r['risk_adjusted_score']`).                                                                                 | Non-functional side effects make pipeline state order-dependent.                                                                                                                                                                        | Refactor `normalize_universe_liquidity_scores` to return updated dictionary copies or explicit scores without mutating inputs, moving liquidity score normalization into `scoring.py`/`liquidity.py`.                                                                                                                                                                                                                                                                            |
| **TD-08** | **MEDIUM**   | Backtest Engine        | Backtest module (`scripts/lib/backtest.py`) combines slicing, execution, and calibration in a single file. | `scripts/lib/backtest.py` is 1000+ lines mixing dataset slicing, market execution eligibility, confidence calibration, walk-forward, and regime evaluation.                                                                                                              | High file complexity makes backtesting code hard to navigate and extend.                                                                                                                                                                | Split `backtest.py` into focused submodules (`execution.py`, `walk_forward.py`, `calibration.py`), enforcing characterization parity tests (`old_output == new_output`) with explicit floating-point tolerance rules prior to refactoring.                                                                                                                                                                                                                                       |
| **TD-09** | **LOW**      | Database / Schema      | Dead / unused SQL schema file in repository (`scripts/audit_trail_schema.sql`).                            | `scripts/audit_trail_schema.sql` exists but is never referenced in python backend, tests, or CI workflows.                                                                                                                                                               | Causes developer confusion regarding active storage layer.                                                                                                                                                                              | Document as optional audit database reference schema or move to documentation directory.                                                                                                                                                                                                                                                                                                                                                                                         |
| **TD-10** | **LOW**      | Testing                | Absence of frontend component unit tests, Playwright e2e tests, and line/branch coverage reporting.        | `scripts/tests/` contains 20 Python backend test files, but `src/` has 0 Vitest or Playwright tests, and `pytest --cov` line/branch coverage is not measured in CI.                                                                                                      | UI regressions or untested backend code branches must be verified manually.                                                                                                                                                             | Introduce Vitest for frontend component testing, Playwright for e2e SSG build verification, and `pytest --cov` line/branch coverage gates in Phase 9.                                                                                                                                                                                                                                                                                                                            |
