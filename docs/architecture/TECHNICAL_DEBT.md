# Technical Debt Inventory

This document provides a comprehensive inventory of technical debt identified across the repository during the audit phase. No items in this inventory have been modified or refactored during Phase 0.

| ID        | Severity     | Area                   | Problem                                                                                                    | Evidence                                                                                                                                                                                                                       | Impact                                                                                                                                                                    | Proposed Direction                                                                                                                                                                                                                                                                  |
| --------- | ------------ | ---------------------- | ---------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **TD-01** | **CRITICAL** | Quant Engine           | Circular import dependency between `risk.py` and `recommendation.py`.                                      | `scripts/lib/risk.py` imports `from scripts.lib.recommendation import VALID_MARKET_REGIMES, calculate_risk_adjusted_score`. `scripts/lib/recommendation.py` imports `from scripts.lib.risk import calculate_t25_risk_metrics`. | Tight coupling between quantitative risk calculations and recommendation scoring. Prevents independent execution and testing of the risk module.                          | Decouple shared scoring functions (`calculate_risk_adjusted_score`) and constants (`VALID_MARKET_REGIMES`) into `scripts/lib/config.py` or a dedicated `scoring.py` module, establishing a clean unidirectional import graph (`config` -> `risk` -> `scoring` -> `recommendation`). |
| **TD-02** | **HIGH**     | Pipeline Orchestration | `scripts/generate_report.py` is a 600+ line God module with excessive responsibilities.                    | Contains CLI parsing, snapshot loading, historical report generation, pipeline execution, history index management, monitoring execution, schema validation, and file persistence.                                             | Difficult to unit test and maintain; changes to historical report logic risk breaking daily production runs.                                                              | Decompose `generate_report.py` into distinct modules: `pipeline_orchestrator.py`, `snapshot_loader.py`, `report_writer.py`.                                                                                                                                                         |
| **TD-03** | **HIGH**     | Data Boundary          | Hardcoded candidate stock universe list in source code (`scripts/lib/vietnam_market.py`).                  | `UniverseProvider.get_default_universe()` defines a static list of 30 stock dictionaries inside python code.                                                                                                                   | Adding or modifying tracked stocks requires python source code edits and deployment. Does not support point-in-time historical universe membership (`Universe(as_of=T)`). | Externalize universe candidate definitions into JSON/YAML configuration files and introduce point-in-time historical universe resolution (`Universe(as_of=T)`).                                                                                                                     |
| **TD-04** | **HIGH**     | Frontend Loader        | Frontend loader contains fallback synthetic data generation (`src/data/loader.ts`).                        | `src/data/loader.ts` generates dummy recommendation objects when network fetch fails.                                                                                                                                          | Risks displaying stale or misleading mock quantitative recommendations to end-users if build artifacts are missing.                                                       | Remove synthetic fallback recommendation generators from frontend loader; return explicit error/empty UI states.                                                                                                                                                                    |
| **TD-05** | **MEDIUM**   | Quant Engine           | Quantitative configuration parameters are re-exported in `recommendation.py`.                              | `SIGNAL_MODEL_VERSION`, `SIGNAL_WEIGHTS`, etc., are defined in `config.py` and re-assigned in `recommendation.py`.                                                                                                             | Creates import redundancy and confusion over canonical parameter sources.                                                                                                 | Standardize all parameter imports directly from `scripts.lib.config`.                                                                                                                                                                                                               |
| **TD-06** | **MEDIUM**   | Quant Engine           | In-place mutation of recommendation payloads during universe liquidity score normalization.                | `normalize_universe_liquidity_scores` in `scripts/lib/risk.py` mutates recommendation dictionary items in-place (`r['risk_metrics']['liquidity_score']` and `r['risk_adjusted_score']`).                                       | Non-functional side effects make pipeline state order-dependent.                                                                                                          | Refactor `normalize_universe_liquidity_scores` to return updated dictionary copies or explicit scores without mutating inputs.                                                                                                                                                      |
| **TD-07** | **MEDIUM**   | Backtest Engine        | Backtest module (`scripts/lib/backtest.py`) combines slicing, execution, and calibration in a single file. | `scripts/lib/backtest.py` is 1000+ lines mixing dataset slicing, market execution eligibility, confidence calibration, walk-forward, and regime evaluation.                                                                    | High file complexity makes backtesting code hard to navigate and extend.                                                                                                  | Split `backtest.py` into focused submodules (`execution.py`, `walk_forward.py`, `calibration.py`), enforcing parity tests prior to refactoring.                                                                                                                                     |
| **TD-08** | **LOW**      | Database / Schema      | Dead / unused SQL schema file in repository (`scripts/audit_trail_schema.sql`).                            | `scripts/audit_trail_schema.sql` exists but is never referenced in python backend, tests, or CI workflows.                                                                                                                     | Causes developer confusion regarding active storage layer.                                                                                                                | Document as optional audit database reference schema or move to documentation directory.                                                                                                                                                                                            |
| **TD-09** | **LOW**      | Testing                | Absence of frontend component unit tests and Playwright e2e tests.                                         | `scripts/tests/` contains 20 Python backend test files, but `src/` has 0 Vitest or Playwright tests.                                                                                                                           | UI regressions or broken component state transitions must be verified manually.                                                                                           | Introduce Vitest for frontend component testing and Playwright for e2e SSG build verification.                                                                                                                                                                                      |
