# Generated Artifacts, Publishing & Atomic Transactions

This document specifies the published static artifacts, schema governance, atomic transaction mechanics, locking, and provenance tracking in **VN Invest** (`area44-labs/vn-invest`).

---

## 1. Published Static Artifacts Overview
All report outputs generated by the production pipeline are published to `generated/` as static JSON files, serving as the single source of truth for the React frontend and monitoring subsystems.

```text
generated/
├── recommendations.json    # Canonical stock recommendations payload (schemas/v2/recommendations.schema.json)
├── market.json             # Market regime, breadth, and benchmark summary
├── monitoring.json         # Operational quality checks and drift result
├── performance.json        # Pipeline stage runtimes and provider metrics (schemas/v2/performance.schema.json)
├── provenance.json         # Data source provenance and dataset hash manifest
└── history/
    ├── index.json          # Historical reports index manifest
    └── YYYY-MM-DD.json     # Point-in-time recommendation snapshot for date YYYY-MM-DD
```

---

## 2. Atomic Publishing Architecture

To prevent corrupt or partial writes from breaking production artifacts during execution, artifact publishing is managed isolated in `scripts/artifacts/`.

```text
scripts/artifacts/
├── publisher.py     # Main ArtifactPublisher orchestrating atomic publishing
├── transaction.py   # ArtifactTransaction directory staging and POSIX file lock
├── manifest.py      # History index manifest management
├── provenance.py   # ProvenanceManifest creation and validation
└── recovery.py     # Transaction recovery and interrupted state cleanup
```

---

## 3. Atomic Transaction Lifecycle

To guarantee single-writer file integrity and zero corrupt writes during publication:

1. **POSIX File Lock (`ArtifactLock`)**: Acquires single-writer lock on `generated/.generated.lock` via `fcntl.flock(LOCK_EX | LOCK_NB)` in `scripts/artifacts/transaction.py`.
2. **Staging Directory**: Writes candidate files into temporary staging directory `generated/.staging_<id>`.
3. **Pre-Commit Validation**: Validates all staged JSON files against schema registry (`scripts/schema/registry.py`) before modifying target files.
4. **Atomic Directory Swap**: Swaps staging directory contents into `generated/`.
5. **Rollback & Recovery**: If publishing fails, restores target files from backup directory `generated/.backup_<id>` and cleans up temporary directories via `recover_interrupted_publish()`.
